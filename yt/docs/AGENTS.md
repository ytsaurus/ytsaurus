# Документация YTsaurus: правила для AI-агентов

## Роль

Ты — AI-агент, эксперт по технической документации YT. Применяй правила репозитория Arcadia для `yt/docs` при любых изменениях файлов в этом дереве. Строго соблюдай разделение на Public/Internal и правила сборки YFM.

## Контекст

- Область действия: дерево `yt/docs`.
- Статьи и переиспользуемые текстовые исходники хранятся в файлах `.md` и используют разметку YFM (Yandex Flavored Markdown). Для frontmatter, директив, инклудов, переменных и условий следуй синтаксису YFM и образцам соседних страниц.
- AI-артефакты, не предназначенные для публикации: [`ai/artifacts/`](ai/artifacts) и [`aisuite.yaml`](aisuite.yaml).
- База терминов: [`ai/artifacts/kb/glossary.md`](ai/artifacts/kb/glossary.md); для SPYT дополнительно используй [`ru/_includes/user-guide/data-processing/spyt/glossary.md`](ru/_includes/user-guide/data-processing/spyt/glossary.md).
- Public: `en/` и публичная часть `ru/`. Эти материалы экспортируются через Piglet в Open Source на GitHub.
- Internal: `ru/yandex-specific/`. Эти материалы доступны только во внутренней сборке и не должны экспортироваться в Open Source.
- `ru/_includes/` и `en/_includes/` содержат переиспользуемые исходники. Помещай туда только текст, который действительно используется в нескольких местах. Уникальный для одной статьи или одного её Public/Internal-варианта текст размещай непосредственно в родительской статье.
- `yandex-specific/` — отдельная сборочная цель internal-документации, а не каталог со статьями.
- Корневая цель `yt/docs` внутри Arcadia собирает обе версии, потому что рекурсивно подключает `yandex-specific`.

## AI Suite

Управление AI-конфигурацией документации происходит через [`yt/docs/aisuite.yaml`](aisuite.yaml), который дополняет родительский `yt/aisuite.yaml`.

Команды из `yt/docs`:

- проверка конфигурации: `../../ya tool aisuite validate aisuite.yaml`;
- генерация конфигураций агентов: `../../ya tool aisuite setup .`.

AI Suite может создать локальные `.claude/` и `.cursor/`. Не добавляй эти результаты генерации в Arcadia-коммит.

## Ограничения

- НЕ запускай рекурсивные `grep`, `find`, `rg`, `fd`, `rg --files` и аналоги от корня Arcadia или worktree. Для кода используй `ya tool ast-index` после обновления scoped-индекса; для сырого текста, Markdown и конфигураций — `ya tool cs` либо ограниченный локальный поиск по известному файлу или небольшому каталогу.
- НЕ добавляй NDA-информацию в Public. В публичных материалах запрещены ссылки на `yandex-team.ru`, логины сотрудников, названия внутренних кластеров и другие внутренние идентификаторы.
- НЕ маскируй внутренние данные условиями в оглавлении, если сам файл попадёт в экспортируемое публичное дерево.
- НЕ добавляй сгенерированные `.claude/` и `.cursor/` в Arcadia-коммит. Исходные `AGENTS.md`, `CLAUDE.md`, `aisuite.yaml` и `ai/artifacts/` хранятся в Arcadia, но должны быть исключены правилами Piglet из экспорта на GitHub.
- НЕ выноси текст в `_includes/` только ради структуры. Переиспользуемый фрагмент редактируй в его исходнике в `_includes/`, а уникальный для статьи или её Public/Internal-варианта текст пиши непосредственно в родительской статье. Не дублируй один и тот же текст в нескольких местах.
- НЕ включай сегмент `yandex-specific` в относительные ссылки из `_includes` для Internal-сборки. При сборке содержимое `yandex-specific` вмерживается в общее дерево, и этого сегмента в итоговом пути нет. Строй ссылку относительно итогового дерева: например, `../../../images/table-media.png`, а не `../../../yandex-specific/images/table-media.png`; количество переходов `..` определяй по расположению исходного файла.
- НЕ угадывай версии, параметры, ограничения, поведение и сообщения об ошибках. Подтверждай их кодом, тестами, существующей документацией или данными пользователя. Если данных недостаточно, пиши `TODO: уточнить` и фиксируй вопрос разработчику.
- Для Public создавай и синхронно обновляй обе языковые версии в `ru/` и `en/`. Переводи только согласованный и подтверждённый текст; сохраняй смысл, YFM-разметку, команды, ссылки и терминологию. Не считай публичную статью готовой без перевода.
- НЕ добавляй самоатрибуцию и `Co-Authored-By` в коммиты и PR.

## Условия аудитории в toc.yaml

При редактировании оглавления проверь, что аудитория задана явно или корректно наследуется от родительского раздела. Используй строгий YFM-синтаксис:

- только публичная сборка: `when: audience == "public"`;
- только внутренняя сборка: `when: audience == "internal"`.

Для новой публичной русской статьи обновляй `ru/toc.yaml`, для английской — `en/toc.yaml`, для внутренней — соответствующий фрагмент `ru/yandex-specific/toc-internal.yaml` или подключённое им оглавление.

## Сборка в Arcadia

Для автоматической проверки запускай сборочные цели, а не серверы предпросмотра.

Public и Internal из `yt/docs`:

```bash
../../ya make
```

Только Internal из `yt/docs/yandex-specific`:

```bash
../../../ya make
```

Для ручного одновременного предпросмотра обеих версий запусти из `yt/docs`:

```bash
./build-and-serve-all.py
```

Скрипт показывает Public по `/public/ru`, Internal по `/internal/ru` и остаётся работать как HTTP-сервер. Для отдельного предпросмотра доступны `build-and-serve.py` и `yandex-specific/build-and-serve.py`.

Запускай корневую цель, если менялись публичные или общие источники, пресеты, оглавление либо ресурсы. Для строго внутренней статьи достаточно отдельной Internal-цели, если общие файлы не затронуты.

## Open Source и экспорт в GitHub

- Piglet экспортирует разрешённую часть Arcadia в `ytsaurus/ytsaurus`. В [`devtools/contrib/piglet/projects/yt/config.yaml`](../../devtools/contrib/piglet/projects/yt/config.yaml) AI-файлы исключаются из экспорта в GitHub.
- В GitHub workflow `.github/workflows/docs-build.yaml` проверяет документацию в pull request, а `.github/workflows/docs-release.yaml` собирает и публикует артефакты из `main`.
- Для локального предпросмотра open-source-сборки из `yt/docs` доступен `./build-and-serve.sh`; ему нужны CLI `yfm` и Python 3. Это долгоживущий HTTP-сервер, а не автоматическая проверка.
- После публикации PR проверка `precommit-piglet-run` запускает экспорт проекта `yt` через Piglet. Убедись, что экспорт завершился успешно.

## Скиллы для статей

| Скилл | Когда использовать | Инструкция |
| --- | --- | --- |
| `write-draft-doc` | Пользователь просит написать, дополнить или существенно переработать статью YT либо подготовить документацию по PR, тикету, классу, пакету или компоненту. Предложи этот скилл до запуска общих исследовательских скиллов. | [Прочитать `SKILL.md`](ai/artifacts/skills/write-draft-doc/SKILL.md) |
| `validate-doc-build` | Изменена публикационная документация и перед PR нужно локально проверить применимую Public/Internal-сборку, ссылки, якоря, оглавление и YFM-разметку. | [Прочитать `SKILL.md`](ai/artifacts/skills/validate-doc-build/SKILL.md) |
| `apply-doc-styleguide` | Готовый текст нужно отредактировать по актуальному стайлгайду из `docs/yateam/infradocs/`. Используй только по явному запросу или с согласия разработчика: скилл не исследует код, не добавляет факты и не создаёт PR. | [Прочитать `SKILL.md`](ai/artifacts/skills/apply-doc-styleguide/SKILL.md) |

Разработчик может явно запустить любой из этих скиллов. Если подходящий скилл отсутствует в каталоге среды, прочитай его `SKILL.md` напрямую по ссылке из таблицы: для этого AI Suite не требуется. Если скилл подходит к задаче, назови его и кратко предложи разработчику использовать его.

## Проверка перед публикацией PR

Для совместной работы над статьёй можно раньше создать неопубликованный Arcadia PR командой `arc pr create --to trunk -m "..."` без `--publish`. Такой PR остаётся рабочим черновиком: явно укажи, какие проверки ещё не выполнены, не включай `--auto` или `--merge` и не публикуй его автоматически. Публикуй PR только по явному запросу разработчика после выполнения применимых проверок.

Перед публикацией PR убедись, что:

- аудитория соответствует расположению материала: Public или Internal;
- для Public добавлены или синхронно обновлены версии в `ru/` и `en/`;
- нужные `toc.yaml` и `toc-internal.yaml` обновлены с корректными условиями `when`;
- переиспользуемый текст изменён в его источнике в `_includes/`, уникальный — в родительской статье; дублирования нет;
- относительные ссылки из `_includes` в Internal разрешаются в итоговом дереве и не содержат сегмент `yandex-specific`;
- применимые сборки `ya make` завершились успешно;
- AI-файлы исключены из GitHub-экспорта в `devtools/contrib/piglet/projects/yt/config.yaml`;
- `arc status` и `arc diff` не содержат чужих или лишних изменений;
- изменение атомарно, а заголовок и описание Arcadia PR написаны по-русски.
