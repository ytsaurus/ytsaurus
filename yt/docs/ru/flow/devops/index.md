# Эксплуатация {{product-name}} Flow

В этом разделе описано, как запустить пайплайн, проверить его состояние и разобраться с остановкой обработки. Команды предполагают, что у вас есть доступ к кластеру и права на узел пайплайна; вместо `//path/to/pipeline`, `<cluster>` и `<operation-id>` подставьте свои значения.

## Развёртывание {#deployment}

Для первого запуска выполните [первичный деплой в Vanilla-операции](vanilla/initial-deploy.md). Контроллер и воркеры будут запущены как задачи одной операции. Для джоб в Docker/CRI, в том числе в типовой установке Kubernetes, прочитайте [про окружение и сеть Docker-джоб](vanilla/docker-environment.md): примеру C++ не нужен отдельный образ, но могут потребоваться настройка разрешения имени кластера и доступ к прокси извне. Flow по умолчанию создаёт и монтирует внутренние таблицы вместе с пайплайном. Если пайплайн использует внешний стейт, который вы обслуживаете самостоятельно, перед созданием таких таблиц выберите [тип таблиц внешнего стейта](state-tables-choice.md) с учётом доступности и стоимости.

## Запуск Flow {#launch-flow}

Создайте конфигурацию и запустите пайплайн по [инструкции для Vanilla](vanilla/initial-deploy.md#run). Перед запуском проверьте объекты и права, которые нужны новой версии.

## Инструкции по развёртыванию {#deployment-pages}

Для изменения действующего пайплайна используйте [операции](vanilla/pipeline-operations.md), [релизы](vanilla/releases.md), [настройку доступа](vanilla/security.md) и [логи](vanilla/diagnostics/logs.md).

## Управление {#lifecycle}

Используйте [`yt flow`](../tools/cli.md) для запуска, остановки, паузы и просмотра состояния пайплайна. Остановка через `stop-pipeline` дренирует промежуточные буферы; `pause-pipeline` приостанавливает обработку без дрейна. [Удаление пайплайна](vanilla/pipeline-operations.md#remove) отдельно отменяет Vanilla-операцию и удаляет узел с внутренними таблицами Flow. Пользовательские таблицы External State за пределами узла остаются.

Для обновления, хотфикса или отката версии следуйте [правилам релизов](vanilla/releases.md). Передавайте токен и другие секреты по [правилам доступа](vanilla/security.md); не помещайте их в спеку или образ.

## Когда прогресс остановился {#investigate}

Сначала запросите состояние и представление пайплайна, затем сопоставьте их с [логами контроллера и воркеров](vanilla/diagnostics/logs.md). [Диагностика](diagnostics.md) помогает найти проблемную джобу, [профилирование](profiling.md) — источник нагрузки или зависания, а [типовые проблемы](troubleshooting.md) связывают наблюдение с безопасным следующим действием.
