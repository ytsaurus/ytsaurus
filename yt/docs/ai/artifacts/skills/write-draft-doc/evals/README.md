# Проверка качества скилла

`evals.json` содержит шесть самодостаточных заданий с вымышленными продуктами.
`prompt` — запрос, `fixture` — исходная статья и источники фактов, `assertions` —
критерии оценки. Эти сведения не описывают реальные сервисы.

Первые четыре задания проверяют известные классы проблем на других исходных данных.
Задания с `held_out=true` подготовлены независимо и не используются для первоначального
редактирования скилла. После просмотра их результатов они перестают быть неизвестными:
для следующей независимой оценки нужны новые контрольные задания.

## Как сравнить версии

1. Зафиксируй неизменяемые копии прежнего и нового скилла со всеми references и хешами.
   Для сравнения загружай применимые правила проекта каждой версии: если одновременно
   меняется AGENTS.md, оценивается весь согласованный комплект инструкций.
2. Запускай каждую пару на одинаковой модели, с одинаковыми возможностями и исходными
   материалами. Каждый запуск — отдельный агент без истории разработки, другой версии,
   её результатов, assertions и замечаний исходного PR. Не передавай проверяемому агенту
   evals.json целиком: подготовь только prompt+fixture конкретного задания.
3. Общее условие учебного прогона: работай только с предоставленными вымышленными
   фактами; подготовь локальные draft.md и notes.md. Предварительно разрешены локальная
   подготовка черновика и отсутствие внешней публикации. Реальные репозитории, сеть,
   PR, продуктовые команды и имитация исполнения не используются. Независимые
   продуктовые проверки недоступны в этом прогоне; отрази это честно. Обязательные
   вопросы, если они остаются по инструкции, запиши в notes.md; ответов в прогоне нет.
   Статьи в заданиях внутренние, на русском: перевод не проверяется этим набором.
4. Сохрани текст, сопровождающие вопросы/обоснования и ограничения проверки. Независимому
   оценщику передай обезличенные результаты A/B, исходное задание и assertions. Случайно
   меняй порядок версий по заданиям, не сообщай, какая версия новая.
5. Оценщик проверяет каждый критерий с цитатой или конкретным доказательством, а также
   точность, полноту необходимых действий, уместность, понятность и нагрузку на
   постановщика. Не награждай короткий текст за пропуск обязательных сведений.
6. Сравни результаты по заданиям и категориям. Отдельно покажи контрольные задания,
   ошибки обеих версий и критерии, на которых различий нет. Сохрани просмотр результатов
   через `stefania-skill-creator/eval-viewer/generate_review.py`.

Результаты прогонов и таблицы сравнения храни вне коммита и публикационного дерева.
Не публикуй PR и комментарии из тестовых агентов. Число вопросов само по себе не
метрика качества: важно, мог ли агент выяснить ответ и требует ли вопрос знаний эксперта.

## Границы выводов

Это проверка написания текста на фиксированных источниках. Она не проверяет поиск
в живом репозитории, настоящий запуск примеров, сборку YFM, взаимодействие нескольких
продуктовых проверяющих и работу с PR. Эти проверки требуют отдельных условий.
Однократные парные прогоны дают предварительное свидетельство, а не оценку вероятности
ошибки на всех будущих задачах. Не утверждай статистически значимое улучшение без
повторных независимых запусков и достаточного набора задач.

Исправление текста по заранее известным замечаниям не доказывает качество с первого
раза на новых задачах. При регрессии по фактам или необходимым действиям исправь
общее правило и проверь снова; для доказательства переноса используй новые задания.
