# Ручной пилот Gena Review для документации YT

Действие **Gena Review документации YT — ручной пилот** в [a.yaml](../../../a.yaml)
запускается вручную из проверок PR в trunk. Для пилота выбирайте опубликованную
итерацию: CI не позволяет сочетать `on-demand` с `mode: publish`.
Оно использует штатный Tasklet Gena Review и публикует замечания и итог в PR.
Проверка необязательна для слияния; автоматический Ship отключён.

## Инструкции

[gena-review.yaml](../../../gena-review.yaml) подключает [оформление](style.md),
[факты](facts.md) и [согласованность RU/EN](ru-en.md), а также исходные правила
проекта, стайлгайд, глоссарий, профиль аудитории и карту кодовой базы.
Эти файлы входят в набор инструкций проверяемой версии целиком; одной ссылки
из Markdown для их подключения недостаточно. Команда сопровождает их вручную.
Дополнительные правила для изображений и глоссарий SPYT ревьюер читает по
применимости. Непрочитанные источники должны быть указаны как ограничения.

Правила документации применяются к `yt/docs/**`. При смешанном PR штатный
Gena Review рассматривает полный diffset, а для других проектов собирает их
собственные инструкции. Включён отдельный проверяющий замечания — Verifier.
Ревью не заменяет сборку документации, проверку ссылок и экспорт Piglet.

## Подготовка первого запуска

1. Влейте конфигурацию с `ship.enabled: false` в trunk **до первого запуска**.
   Gena Review читает разрешения публикации из базовой ревизии PR: добавление
   запрета только в проверяемую ветку ещё не отключает Ship. Не запускайте
   ревью на PR, который впервые добавляет эту конфигурацию.
1. Проверьте делегацию служебного секрета для `yt/docs/a.yaml` по
   [штатной инструкции](https://a.yandex-team.ru/arcadia/taxi/ai/gena-review/docs/quickstart.md).
   Если её нет, запросите у владельцев Gena Review делегирование именно этому CI scope.
1. Для первого пробного запуска оставьте параметры формы по умолчанию:
   конфигурация `gena-review`, `tasklet_label=stable`, `launch_workspace=neutral`,
   внешний аккаунт Tasklet `/root/generic/gena_review_dev`.
   Оплата токенов и аккаунт Solver берутся из общей конфигурации агента.
   Это подключение предназначено для пилота; перед регулярными запусками
   нужна командная конфигурация с согласованными оплатой и вычислительной квотой.
1. Откройте опубликованный документационный PR с этой конфигурацией уже в его
   базовой версии и запустите действие вручную. Не запускайте повтор, пока
   предыдущий запуск той же итерации ещё выполняется.

Доступ к запуску ограничен теми же командами, что и CI документации YT.
Настройки IDE через AISuite и запуск из Трекера для этого сценария не требуются.

## Проверка подключения

Из корня Аркадии выполните:

```bash
./ya tool gena-review-cli diagnostics validate-config yt/docs
./ya tool ci validate yt/docs/a.yaml
```

В живом запуске проверьте точные PR и diffset, фактически загруженные инструкции,
результат Verifier, опубликованные замечания и итог. Успешная проверка YAML
или технический статус Tasklet сами по себе не подтверждают завершённое ревью.

Для приёмки нужны известное нарушение стайлгайда, фактическое противоречие
с доступным первоисточником и случай с недоступным подтверждением. Ревьюер
должен обнаружить первые два и явно обозначить ограничение в третьем.
Для Internal не требуется английская версия; для Public проверяется смысловое
соответствие RU/EN. Повтор на новой итерации должен проверять именно её.
Убедитесь, что робот не выставляет Ship и не изменяет исходники.

Ошибка запуска, отсутствие результата или недоступный источник не считаются
успешным ревью. Ссылки на ошибочный CI/Solver запуск нужны для обращения в
[поддержку Gena Review](https://messenger.360.yandex.ru/#/join/5e588827-4539-4c53-b83f-e74a6622faca).

Конфигурация и этот каталог исключены из экспорта в GitHub правилами Piglet.
